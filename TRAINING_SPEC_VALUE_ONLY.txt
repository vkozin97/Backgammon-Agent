Цель проекта: реализовать систему обучения 12 агентов для игры в нарды в режиме value-only, где модель предсказывает вероятность победы из текущего состояния, а качество оценивается в лиге матчей между агентами и против двух фиксированных оппонентов.

Область реализации:
1) Среда и игровые эпизоды.
2) Набор из 12 обучаемых агентов, разбитых на 3 архитектурные группы.
3) Контроллер лиги и генерации партий.
4) Общее хранилище истории шагов.
5) Контроллер обучения с батч-семплированием из истории.
6) Контроллер валидации и логирования метрик.
7) Система чекпоинтов и воспроизводимости.

Состав агентов:
Всего 12 агентов = 3 архитектурные группы по 4 агента в каждой группе.
Группа A: MLP с 3 полносвязными слоями.
Группа B: MLP с 6 полносвязными слоями.
Группа C: сверточная обработка двух векторов с фишками, затем MLP-голова из 3 полносвязных слоев.

Вход модели:
Расширенный вектор состояния позиции без значений костей и без номера хода.

Выход модели:
Скаляр p_win в диапазоне [0, 1], интерпретация: вероятность победы текущего игрока из текущей позиции.

Dropout-требования:
Dropout обязателен во всех архитектурах.
Рекомендуемая стартовая схема:
- Группа A (3 FC): dropout после первого и второго скрытого слоя, p_dropout = 0.10.
- Группа B (6 FC): dropout после каждого скрытого слоя, кроме последнего перед выходом, p_dropout = 0.15.
- Группа C (Conv + 3 FC): dropout после конкатенации признаков перед FC-головой и после первого скрытого FC-слоя, p_dropout = 0.10.
Вынести p_dropout и позиции применения dropout в конфиг, чтобы можно было менять без изменения кода.

Функция потерь:
Используется только value-loss.
Выбор конкретной формы через конфиг: BCEWithLogitsLoss или MSELoss (дефолт BCEWithLogitsLoss при наличии логитов).
Если используется BCEWithLogitsLoss, выходной слой модели должен возвращать логит, а преобразование в вероятность делать через sigmoid только для инференса и метрик.

Лига и генерация партий:
Обучаемые агенты играют матчи каждый с каждым.
Дополнительно каждый обучаемый агент играет против двух фиксированных оппонентов:
1) RandomAgent: полностью случайный выбор допустимого хода.
2) BaselineAgent: простой самописный эвристический агент.
Число партий на каждую пару задается гиперпараметром games_per_pair.

Хранилище истории:
Нужно единое replay-хранилище шагов из всех сыгранных партий.
Для каждого шага сохранять:
- state_vector,
- id текущего агента,
- id оппонента,
- id партии,
- индекс шага в партии,
- номер эпохи генерации,
- терминальный исход партии с точки зрения текущего игрока на шаге,
- timestamp или recency_index для приоритета свежих данных.

Семплирование для обучения:
Использовать смешанную стратегию:
- 80% батча из свежих данных (recency sampling),
- 20% батча равномерно по всему буферу (uniform sampling).
Параметры alpha_recency=0.8 и alpha_uniform=0.2 сделать конфигурируемыми.
Реализация recency sampling может быть через окно последних эпох или через вероятности, убывающие по времени; выбор механики вынести в конфиг.

Коррелированность данных:
Партий будет много, но для устойчивости все равно ограничить максимальное число сэмплов из одной и той же партии в одном батче параметром max_samples_per_game_in_batch.
Если параметр выключен, логировать долю повторов по game_id внутри батча.

Контур эпохи:
Каждая эпоха включает 4 стадии:
1) Генерация новых партий лиги.
2) Добавление шагов в replay-хранилище.
3) Обновление параметров всех 12 агентов.
4) Оценка качества и логирование метрик.

Обновление агентов и CUDA-организация:
Обучение и инференс организовать в 3 прохода по архитектурным группам (A, B, C), а не 12 полностью независимых одиночных проходов.
Внутри группы обрабатывать батчи максимально векторизованно.

Метрики по итогам каждой эпохи:
Для каждого из 12 агентов логировать:
- train_loss_epoch,
- winrate против каждого из 13 оппонентов (11 обучаемых + 2 фиксированных),
- aggregate_winrate_vs_trainable,
- winrate_vs_random,
- winrate_vs_baseline,
- среднюю длину партии,
- throughput генерации партий (games/sec),
- throughput обучения (steps/sec),
- использование GPU памяти (если доступно).

Графики:
Для каждого агента строить график winrate по эпохам против 13 оппонентов.
Дополнительно строить агрегированные графики по архитектурным группам: средний winrate группы против random, baseline и остальных обучаемых.

Чекпоинты и артефакты:
Сохранять после каждой эпохи:
- веса моделей 12 агентов,
- состояния оптимизаторов,
- состояние replay-индексов,
- конфиг запуска,
- метрики эпохи в машиночитаемом формате.
Обеспечить возможность полного возобновления обучения из checkpoint_dir.

Критерии приемки реализации:
1) Система стабильно запускает минимум 3 эпохи полного цикла без ручного вмешательства.
2) Для всех 12 агентов корректно обновляются веса и сохраняются чекпоинты.
3) Replay-хранилище заполняется и семплирует батчи в пропорции 0.8 recency и 0.2 uniform.
4) По каждой эпохе сохранены winrate-метрики агента против 13 оппонентов.
5) Строятся и сохраняются графики winrate по эпохам для каждого агента.
6) Поддерживается восстановление из checkpoint с продолжением обучения без рассинхронизации метрик.

Ограничения первой версии:
- Реализуется только value-only обучение.
- Любые дополнительные регуляризаторы и альтернативные термы в loss не включать.
- Статистические критерии значимости в сравнении winrate не обязательны в первой версии.

Требования к качеству кода:
- Четкое разделение модулей: env, agents, league, replay, trainer, evaluator, logging, plotting.
- Все гиперпараметры должны задаваться конфигом без хардкода в логике обучения.
- Ключевые этапы пайплайна покрыть минимальными автотестами: загрузка конфига, один шаг генерации, один шаг обучения, сохранение и восстановление checkpoint.
