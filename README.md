# Backgammon

Creating a neural network agent to play backgammon

&nbsp;



Backgammon RL Environment (C++ core + Python bindings)



Описание проекта



Проект представляет собой высокопроизводительную среду для коротких нард (Backgammon), предназначенную для дальнейшего использования в обучении нейронных сетей (reinforcement learning, self-play).



Архитектура построена следующим образом:



\* игровая логика полностью реализована на C++

\* Python используется только для взаимодействия, обучения и оркестрации

\* связь C++ и Python реализована через pybind11

\* для тестирования логики используется CLI и Pygame viewer



Основная цель — получить быструю, масштабируемую среду, пригодную для self-play и последующего обучения policy/value сети.

Архитектурные принципы



1\. Вся игровая логика должна находиться в C++.

2\. Python не должен рассчитывать игровые фичи.

3\. Move представляет собой полный ход (оба кубика), а не одно перемещение.

4\. Агент всегда выбирает индекс из списка legal\_moves.

5\. Никакие глобальные состояния не используются.

6\. Среда не должна мутироваться вне методов класса BackgammonEnv.



C++ Core



Основной класс среды



class BackgammonEnv {

public:

void reset\_standard();

Dice roll\_dice();

Dice current\_dice() const;



```

void legal\_moves(std::vector<Move>\& out) const;

float step\_apply(const Move\& m, bool\& done);



void get\_state\_raw(int16\_t out\[53]) const;



const GameState\& state() const;

```



};



reset\_standard()

Инициализирует стандартную стартовую позицию коротких нард.



roll\_dice()

Генерирует бросок кубиков и сохраняет его в состоянии среды.



current\_dice()

Возвращает текущие значения кубиков.



legal\_moves(out)

Заполняет вектор out всеми допустимыми ходами для текущей позиции и текущего броска.



step\_apply(move, done)

Применяет ход move к текущему состоянию.

Возвращает reward и флаг done (конец игры).



get\_state\_raw(out)

Возвращает сырой массив состояния длины 53.



Формат состояния (raw state)



Тип: int16\[53]



Индексы:

0–23   мои фишки по пунктам

24–47  фишки соперника

48     mine\_bar

49     mine\_off

50     opp\_bar

51     opp\_off

52     ply (номер полухода)



Это минимальный формат для передачи в Python и для отладки.



Observation API



В среде реализованы два формата observation.



1\. Compact observation

&nbsp;  Размер: 55 float



Предназначен для подачи в нейросеть.



2\. Extended observation

&nbsp;  Размер: 61 float



Содержит дополнительные метрики, рассчитанные в C++:



\* pip count mine

\* pip count opponent

\* количество одиночных шашек

\* anchors

\* и другие производные характеристики позиции



Важно: все вычисления фич выполняются в C++, а не в Python.



Формат хода



struct Move {

uint8\_t from\[4];

uint8\_t to\[4];

};



Каждый Move может содержать до 4 перемещений:



\* обычный ход: до 2 перемещений (оба кубика)

\* дубль: до 4 перемещений



В Python legal\_moves() возвращает массив:

shape (N, 8) dtype uint8



Формат строки:

\[from1, to1, from2, to2, from3, to3, from4, to4]



Если ход использует меньше шагов, неиспользуемые элементы могут быть заполнены специальным значением (например 255).



Python API



Пример использования:



import bg\_env



env = bg\_env.Env(123)



env.reset()

dice = env.roll\_dice()



obs = env.get\_obs\_compact()

obs\_ext = env.get\_obs\_extended()



moves = env.legal\_moves()



reward, done = env.step\_move(moves\[i])



Алгоритм взаимодействия:



1\. reset()

2\. roll\_dice()

3\. получить legal\_moves()

4\. выбрать индекс хода

5\. step\_move(moves\[idx])

6\. повторить

Следующий критический этап



Необходимо реализовать полноценную генерацию ходов:



1\. Использование обоих кубиков в рамках одного Move.

2\. Поддержка дублей (4 перемещения).

3\. Учёт порядка костей (die1->die2 и die2->die1).

4\. Правило максимального использования кубиков.

5\. Рекурсивная генерация последовательностей.

6\. Удаление дубликатов.

7\. Соблюдение правил битья и выхода с бара.



Move должен представлять полный ход за бросок.



План развития под RL



Будущая архитектура обучения:



\* Policy head: распределение по legal\_moves

\* Value head: оценка позиции

\* Self-play генерация партий

\* Возможная интеграция MCTS



В дальнейшем планируется:



\* функция оценки кандидатов без клонирования среды

\* batch environments

\* оптимизация для массовой генерации партий



Ключевые ограничения



\* Python не должен содержать игровую логику.

\* Все фичи должны рассчитываться в C++.

\* Move — это полный ход, а не одиночное перемещение.

\* Среда должна быть детерминированной при фиксированном seed.

\* Архитектура должна быть готова к масштабированию.
